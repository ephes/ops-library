# Python behaviour → Rust test map (metrics-httpd)

Every Python behaviour the port must keep (PLAN.md section 4) and every
allowed difference (section 5.2) gets a Rust counterpart: a fixture case
generated from the Python scripts, a Rust unit test, or a process test.
Each slice fills in its rows; reviewers check coverage per slice. Status:
`pending (Sn)`, `done (Sn)`, or `n/a` with the reason.

Kinds:

- **fixture**: a case in `fixtures/`, generated by `fixtures/generate.py`
  from CPython or a rendered endpoint script (PLAN.md 8.2) and replayed by
  `tests/fixtures.rs` (the `apt_state` family by `tests/apt_state.rs`);
  `tests/test_metrics_httpd_fixtures.py` (`just
  test-metrics-httpd-fixtures`, part of `just test`) fails on drift.
- **unit**: `#[cfg(test)]` tests in `src/**`.
- **process**: `tests/binary.rs` against the built binary.
- **harness**: the parity harness of PLAN.md 8.3 (S3).
